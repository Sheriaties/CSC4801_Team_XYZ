# CSC4810 期末项目：招聘与候选人匹配平台

团队将构建**一个完整的招聘平台**，使用AI编码代理和规范驱动的工作流。该产品是固定的：一个双边市场，其中候选人查找和申请职位，雇主管理申请人，候选人在并发使用下安全地预订面试时间段。

框架、语言、数据库、托管模型和可选增强功能由团队选择。所需的匹配基线和其他可观察行为在产品需求规范中固定；除非明确标记为可选，否则要求是强制性的。

## 评分

期末项目占总课程成绩的**50%**。初步50分的团队总分用于排名预期的十个团队：

| 组件 | 初步分数 |
|---|---:|
| 要求履行（100个原始分数缩放至10分） | 10 |
| 跨团队审计和修复 | 30 |
| 演示 | 10 |
| **用于排名的总分** | **50** |

### 1. 要求履行

学生**必须**为`REQUIREMENTS.md`中的每个功能要求编写自己的单元测试，并在`README.md`中进行映射。仅需要单元测试，包括FP-TEST-1中指定的安全和预订冲突逻辑。评分基于完成的要求数量。学生负责确保其测试正确且完整。

### 2. 跨团队审计和修复

每个团队从**0审计分数**开始。有效的发现和有证据支持的修复会增加审计分数。每份报告和审计行动必须遵循同行评审指南。实时排行榜显示每个团队的审计分数。最终成绩基于团队排名，而不是绝对的审计分数数。

#### 发现分数

| 结果 | 分数 |
|---|---:|
| 安全漏洞 | +2 |
| 功能或性能漏洞 | +1 |
| 环境问题（例如，存储库的`Dockerfile`无法构建或运行） | +0.5 |
| 无效的错误报告 | -0.5 |
| 重复的错误报告 | 0 |

一个根本原因计为一个发现，即使它产生多个症状。

#### 修复分数

| 结果 | 分数 |
|---|---:|
| 有效的修复记录、永久修复提交URL和在修复截止日期前提交的回归证据 | +2 |
| 不正确的修复或回归测试声明 | -0.5 |

#### 存储库可用性

在发布的审计窗口期间，存储库必须保持公开可读。每个不可用的审计窗口小时扣除`0.2`审计分数，最高10分。经讲师确认的GitHub范围停机不计算在内。

### 3. 演示
每个团队将向班级演示其系统并回答有关其实现的问题。演示将根据系统实现的清晰度、完整性和正确性以及团队回答有关其设计和实现的问题的能力进行评分。演示也是展示团队实施的任何可选增强功能的机会。

## 里程碑

| 周 | 必需的里程碑 |
|---|---|
| 1-2 | 组建一个由三人组成的团队并创建一个私有存储库。 |
| 3 | 宣布期末项目和要求。 |
| 3-10 | 构建系统、测试、文档和种子数据。 |
| 11 | 功能冻结。测试必须在`main`分支上通过。 |
| 12 | 在审计窗口前将存储库公开。其他团队从您存储库的`Dockerfile`在最新提交处构建环境并进行同行审计。功能冻结后，仅在`main`上进行错误修复和文档更正。 |
| 12周末 | 完成修复和文档。在`main`上提交确切分级提交的永久URL；其存储库`Dockerfile`必须构建完整环境。 |
| 13-14 | 演示正在运行的系统并回答实现问题。 |

确切的日历日期在课程网站上发布。

## 审计窗口

审计窗口是**课程时区第12周周一至周五的08:00-20:00**。存储库必须在整个该窗口内保持公开可读。迟到或中断的访问将导致罚款。

所有审计都针对另一个团队的源代码进行，位于其`main`分支的最新提交，从存储库的`Dockerfile`构建，在审计员自己的机器上。这是代码审查和本地测试，而不是对实时服务的渗透测试。每个审计员必须遵循同行评审指南。

## 初始存储库

初始存储库提供初始标题、虚拟单元测试函数和示例要求-测试映射表。学生应该使用这个模板，在提交前填写文档、实现和真实单元测试。

演示分支提供了玩具实现、错误报告和修复示例。

## 技术和AI资源

提供了MiMo API订阅，建议使用Claude Code。允许使用其他编码代理，但学生负责任何相关费用。使用AI不会减少对提交代码的理解、审查、测试和保护的责任。
